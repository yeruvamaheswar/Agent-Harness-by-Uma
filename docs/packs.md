# Add-on rule packs

A pack is a short set of rules for one category, such as testing. It adds to your base policy. It never replaces it. The base policy wins every conflict.

This version installs packs into Claude Code, Codex, and Cursor. It reads packs from `catalog/` in your clone, and local packs adopted from your own rules from `.state/packs/local/` (see [Local packs](#local-packs-adopted-from-your-rules)). There is no network fetch, no `@latest`, and no automatic update. Generic support comes in a later version.

| `--platform` | Base install it needs | Where the pack goes |
| --- | --- | --- |
| `claude` | `install claude` | A marker section in `~/.claude/CLAUDE.md`, after the base block |
| `codex` | `install codex` | A marker section in `~/.codex/AGENTS.md`, after the base block |
| `cursor` | `install cursor-files` | Its own file, `~/.cursor/rules/agentic-harness-pack-<author>__<id>.mdc` |

The target folder comes from the base installation receipt, so `CLAUDE_CONFIG_DIR` and `CODEX_HOME` are respected the same way as the base install.

## Format

Each published version is one folder with exactly two files:

```text
catalog/
  index.json                         # generated by `catalog build`; do not edit
  packs/<author>/<id>/<version>/
    pack.json                        # manifest and digest
    rules.md                         # the text that is installed
```

`pack.json` fields. Unknown fields are rejected.

| Field | Rule |
| --- | --- |
| `schemaVersion` | `1` |
| `id` | `author/pack-id`, lowercase letters, digits, single hyphens. Author up to 39 characters, pack ID 3–40. Must match the folder. |
| `name`, `description` | Plain text, at most 60 and 200 characters. No line breaks, HTML, or URLs. |
| `category` | `security`, `writing`, `data`, `testing`, or `agent-design` |
| `version` | Semver. Must match the folder. Published versions never change. |
| `author` | `{ "name", "github" }`. `github` must equal the `author` part of `id`. |
| `license` | `MIT`, `Apache-2.0`, `CC-BY-4.0`, or `CC0-1.0` |
| `minHarness` | Lowest harness software version (`package.json`) that understands this pack |
| `platforms` | Subset of `codex`, `claude`, `cursor`, `generic` |
| `digest` | SHA-256 over every other field plus the `rules.md` text, in a fixed key order. Key order in `pack.json` does not matter. |

`rules.md` limits:

- 8 KB maximum, UTF-8, plain Markdown.
- No HTML or HTML comments, front matter, harness marker strings, zero-width or bidirectional characters, control characters, or encoded-looking runs over 200 characters.
- No scripts or extra files. A folder with any other file, or a symlink, is rejected.

All packs on one platform together may use at most 24 KB of rules.

## Commands

Run from the root of your harness clone.

```sh
npm run harness -- pack list
npm run harness -- pack add yeruvamaheswar/testing-basics@1.0.0 --platform claude
npm run harness -- pack add yeruvamaheswar/testing-basics@1.0.0 --platform claude --approve-sha <digest>
npm run harness -- pack remove yeruvamaheswar/testing-basics --platform claude
npm run harness -- catalog build
```

Use `--platform codex` or `--platform cursor` in the same commands for the other agents. Each platform is installed, verified, and removed separately.

- `pack list` shows the catalog and the installed packs for `claude`, `codex`, and `cursor`, with verification for each.
- `pack add` without `--approve-sha` is a preview. It prints the manifest, the full text, the digest, and the target. For Claude and Codex it shows the line where the block goes. For Cursor it shows the file it will create. It writes nothing.
- `pack add` with `--approve-sha` installs only if the digest equals the text you reviewed. A different digest is refused.
- `pack remove` deletes the pack and its receipt. For Claude and Codex it cuts the pack section; if nothing else changed, the file returns to its exact bytes from before the add. For Cursor it deletes the pack file.
- `catalog build` validates every pack folder and rewrites `catalog/index.json`. Run it after you add a pack version, and review the diff.

The base policy must be installed first. The pack manifest must list the platform in `platforms`.

### Claude Code and Codex: marker sections

The pack goes in its own marker section after the base block, or after the last installed pack:

```text
<!-- BEGIN AGENTIC HARNESS PACK author/id -->
<!-- Agentic harness pack author/id 1.0.0; digest ... -->
## Add-on rule pack: Name (1.0.0)
These rules add to the base Agentic Harness policy. If a rule here conflicts with the base policy, follow the base policy. ...
...rules.md...
<!-- END AGENTIC HARNESS PACK author/id -->
```

### Cursor: one file per pack

Cursor gets one rule file per pack, in the `rules` folder next to the `mcp.json` that `install cursor-files` owns. The base policy is in Cursor User Rules, so `pack add` cannot check that it is there (see [platforms](platforms.md#cursor)). The file holds the same marked block as above, under front matter that makes Cursor load it in every Agent chat:

```text
---
description: Agentic Harness add-on pack author/id 1.0.0
alwaysApply: true
---

<!-- BEGIN AGENTIC HARNESS PACK author/id -->
...same block as above...
<!-- END AGENTIC HARNESS PACK author/id -->
```

The file name replaces the `/` in the pack ID with `__`, for example `agentic-harness-pack-yeruvamaheswar__testing-basics.mdc`. `pack add` refuses if a file with that name already exists. The pack owns the whole file. Any edit, including the front matter, makes verification fail and makes `pack remove` refuse.

The harness writes the precedence sentence. The pack author cannot change it.

## Verification

`verify claude`, `verify codex`, `verify cursor-files`, and `status` report a `packs` array next to the base result.

- Each pack shows `configurationVerified: true` when its section (Claude, Codex) or its whole file (Cursor) matches the receipt.
- Base `configurationVerified` still covers the base install only.
- `behaviorVerified` stays `false`.

To check behavior, start a fresh session of that agent in an empty folder. Ask which add-on packs are active and which policy wins a conflict. Expect the pack ID, its version, and "the base policy".

Receipts are in `.state/installations/packs/<platform>/<author>__<id>.json`, where `<platform>` is `claude`, `codex`, or `cursor`. Backups are in `.state/backups/packs/<platform>/`. Receipts store backup paths relative to the harness root.

The global rules scanner (`rules scan` and the Global rules panel) labels pack sections and Cursor pack files as **Add-on pack**. It reports no drift or missing-agent findings for them, and `rules apply` refuses to change them. A Cursor pack file that lost its markers shows as a malformed finding with no proposal.

## Local packs adopted from your rules

The author name `local` is reserved. An adopt-as-pack proposal from `rules scan` turns one of your own rules into `local/<name>` and installs it on Claude Code, Codex, and Cursor in one approved `rules apply`. See [Global rules](platforms.md#global-rules-beyond-the-harness-policy).

- Local packs live in `.state/packs/local/<name>/<version>/`, with the same two files and the same validation as catalog packs. They are private and ignored by Git. `catalog build` refuses a `catalog/packs/local/` folder.
- They have no `catalog/index.json` entry. Their trust step is the `rules apply` digest, which covers the pack digest and every file change.
- They use the same placement, receipts, verification, and `pack remove` as catalog packs. `pack list` shows them as installed, and `pack add local/<name>@<version>` can reinstall one.
- The manifest is generated: category `agent-design`, platforms `claude`, `codex`, `cursor`, and license `CC0-1.0` as a schema placeholder. The text is not published.

## Limits by platform

- **Cursor** reads rules when a chat starts. Open a new Agent chat after `pack add` or `pack remove`; running chats keep the old rules. Cursor User Rules in the settings UI are separate, and the harness does not write them. File installation is not proof that Cursor loaded the rule; run the fresh-chat check.
- **Codex** reads `AGENTS.md` when a session starts, so start a new session. A global `AGENTS.override.md` replaces `AGENTS.md`; `verify codex` reports it, and packs do not load while it exists. Codex caps how much instruction text it reads, so keep packs few and short.
- **Claude Code** reads `CLAUDE.md` when a session starts. Start a new session after a change.
- The 24 KB limit applies to each platform separately.

## Trust model

A pack is untrusted text. After you approve it, it becomes a global instruction for agents that can run shell commands.

- The digest pins the exact text you read. It does not make the text safe.
- Preview and approval stop accidents. They do not stop a local agent that runs the preview and approves itself.
- The precedence sentence guides the model. It cannot force the model to obey.
- Read every line before you approve. Install few, short packs.

## Recovery

- **Wrong digest:** run `pack add` without `--approve-sha`, read the text again, and use the printed digest.
- **Digest mismatch or index mismatch:** the catalog folder changed after its digest was recorded. Restore it from Git. Published versions never change; publish a new version instead.
- **Extra files:** remove stray files such as `.DS_Store` from the version folder.
- **"Remove packs first":** run the printed `pack remove` commands, then the base `uninstall`. `uninstall cursor-files` refuses while Cursor packs are installed, even though they are separate files, because each pack depends on the base policy.
- **Base uninstall still refuses after pack removal (Claude, Codex):** a base reinstall while a pack was present recorded a file hash that included the pack. Run `install claude` (or `install codex`), then uninstall.
- **"Pack section changed since installation" (Claude, Codex):** the pack section was edited. Undo the edit so the section matches `rules.md` under the harness header, then run `pack remove`. Or delete the section by hand, from its BEGIN line to its END line plus the blank line before it, and delete its receipt. Each add and remove first saves the whole file in `.state/backups/packs/<platform>/`.
- **"Pack file changed since installation" (Cursor):** the `.mdc` file was edited. Undo the edit, then run `pack remove`. Or delete the file and its receipt by hand. `pack remove` saves the file in `.state/backups/packs/cursor/` before deleting it. The backup from `pack add` is empty, because the file did not exist.
- **"No longer exists. Delete the receipt":** the target file was deleted by hand. Delete the named receipt to finish the removal.
- **"An unmanaged file … already exists" (Cursor):** a file with the pack's file name exists but has no receipt. Read it, then move or delete it before `pack add`.
