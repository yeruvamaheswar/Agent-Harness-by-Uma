One rulebook for every AI coding agent.

Rules every agent reads, locks an agent cannot open, and spot checks that show whether the rules held. Explained in nine figures.

Why it exists

The problem

  • Each agent keeps its rules in a different place. Claude Code reads a file in ~/.claude. Codex reads a file in ~/.codex. Cursor reads a setting inside the app. A cloud agent sees only the project folder.
  • Copies drift. You change one by hand, and the others fall behind. Then no one knows which edition an agent has.
  • Written rules are advice. A model can ignore them.
  • A file in the right place does not prove that an agent follows it.

The answer

Rules
One policy, frozen as an approved release. Every agent gets the same text, and its first line names the edition: Harness release 1.4.3.
Locks
A few actions are refused, or stopped for your OK, by the agent's own software. Today that is Claude Code only.
Proof
Three separate levels: configured, tested, behaviorally verified. A file check is never reported as proof of behavior.

The limit stays visible on every page of this project: rules guide a model. They cannot force it.

Fig. 2. Advice, ask rule, lock

A rule has a strength. Advice asks the model. An ask rule makes the software stop and ask you. A lock makes the software refuse. A release needs your approval before anything happens.

  1. Advice

    The rule asks. The model decides.

    Every platform.

  2. Ask rule

    The software stops and asks you.

    8 rules, Claude Code.

  3. Lock

    The software refuses.

    19 rules, Claude Code.

  4. Your approval

    Nothing happens until you approve the exact text.

    Every release.

A lock matches the text of a command. It is a guard, not a sealed room: an unusual form of the command can still pass.

Select an action to see which strength handles it.

Source: controls/controls.json, 6 controls and 27 rules, and knowledge/core.md.

    Skills: one manual step
    
      
    The policy names three skills: grill-me, html-explainer, and render-rules. A fourth, verify, loads only when you ask for it. The sources of all four are in tools/agents/skills/. No harness command installs them yet. Copy each folder to ~/.agents/skills/, and link each into ~/.claude/skills/ for Claude Code. The html-explainer skill also needs the page builder: copy tools/agents/bin/md-view.sh and md-view.template.html to ~/.agents/bin/. Without the skills, an agent still follows the policy. It only lacks the detailed procedures.

    Why it is built this way
    
    
    
      
    DecisionWhyWhat it costs
    
      
        
    You approve a digest, not “the latest”.You see the exact text that every agent will get. A change after the preview stops the publish.One more step for every change.
    
        
    A release never changes.Every install can be compared with a known text. To go back is one command.A one-word fix needs a new version number.
    
        
    A small core, with detail on demand.The policy loads in every session, so every line costs context. Skills and references load only when used.The agent must choose to look things up.
    
        
    In an instruction file, the harness owns one marked block.Your own text in the same file stays. Every write has a backup, a receipt, and an undo.Uninstall refuses when you edited the file after the install.
    
        
    Locks sit outside the model, with a lock on the locks.A refusal that does not depend on what the model decides. The edit tool and the controls command are refused too.Claude Code only. A lock matches command text, so an unusual form can pass.
    
        
    A file check never counts as proof of behavior.“Configured” and “verified” stay different words in every report.Proof needs a real session, and that spends tokens.
    
        
    Cursor gets the rules in one place, by hand.With a rule file as well, the policy loaded twice in every chat, and the two copies differed after each release.One paste for each release.
    
        
    No framework, and two runtime dependencies.Node.js 24 runs the TypeScript directly. There is less to install and less to audit.It needs Node.js 24 or later.
    
        
    The reference search is read-only.An agent can read approved documents. It cannot publish or run a command through the search.It runs on your computer only. Cloud agents have the rules but no search.
