## 1. Single-Agent vs. Multi-Agent Topologies
Do not default to multi-agent setups unless the workflow demands it. Multi-agent systems add massive coordination overhead, multiple points of failure, and complex state tracking.
- **Single-Agent Pattern (Centralized Control):** One primary agent owns the loop. It sequentially classifies intents, retrieves context, calls APIs, and generates a response.
	- *Example:* A customer support agent that checks billing, retrieves an account, and issues a refund.
- **Multi-Agent Pattern (Separation of Responsibilities):** The workflow is split across specialized roles with strict routing logic, input/output contracts, and conflict resolution rules.
	- *Example Roles:* A Planner agent, a Knowledge Retriever agent, a Code Writer agent, a Reviewer agent, and an Execution agent. Useful for parallel work or tasks requiring strict review loops.
## 2. Model Routing in Practice
Stop wasting tokens by using heavy reasoning models for simple extractions.
- **Small/Fast Models:** Use these to extract predictable data into a JSON schema (e.g., pulling `date`, `time`, `doctor_name`, and `appointment_type`).
- **Reasoning Models:** Trigger these only for complex, ambiguous constraints.
	- *Video Example:* If a user says, *"I am going to be traveling next week. I want to avoid mornings or make sure this is happening after my lab results come in,"* route this to a reasoning model. A small model will fail to parse that logic.
## 3. Memory & State: Database Architecture
Memory design is actually data architecture. Do not dump everything into a vector database. Segregate data by access patterns:
- **Workflow State (The "Now"):** Stores the current step, tool results, and confirmation status.
	- *Tech Stack:* Low-latency stores like Redis, DynamoDB, PostgreSQL, or MongoDB.
- **Knowledge Retrieval (RAG):** Stores document chunks with metadata filters.
	- *Tech Stack:* Pinecone, pgvector, Weaviate, ElasticSearch, or OpenSearch.
- **Application State:** Your core business logic database.
- **Long-Term Archive:** Raw conversation logs and historical data.
	- *Tech Stack:* Cheap object storage like an AWS S3 bucket.
- *Security Rule:* For an appointment reschedule, pass *only* the `appointment_id` and `available_slots` to the LLM. Do not casually pass the user's entire medical history through the prompt window just because it exists in the database.
## 4. Tool & Orchestration Guardrails
Your orchestrator (whether custom Python code, LangGraph, or workflow engines like n8n) must enforce strict boundaries.
- **Safer Tool Contracts:** Instead of a vague `update_user` string, enforce explicit fields:
	- `user_id`
	- `field_to_update`
	- `new_value`
	- `reason`
	- `source_request_id`
	- `confirmation_required`
- **The Model Context Protocol (MCP):** Look into MCP as an emerging standardized pattern for exposing tools, resources, and context to your agents safely.
## 5. Trace-Level Evaluation Metrics
Evaluating the "final response" is insufficient. An agent might output a polite, polished answer using the completely wrong retrieved policy. You must log and track these specific metrics asynchronously (using an LLM-as-a-judge + deterministic code):
1. **Intent Accuracy:** Did it route to the right workflow?
2. **Tool Call Success Rate:** Did the API accept the payload?
3. **Invalid Schema Rate:** How often does the model hallucinate bad JSON?
4. **Retrieval Hit Rate:** Did RAG pull the correct document chunk?
5. **Refusal Accuracy:** Did the agent correctly refuse an out-of-scope or unsafe prompt?
6. **Escalation Rate:** How often did it hand off to a human?
7. **Task Completion Rate:** Did the workflow reach the final state?
8. **Cost Per Successful Task:** (Total Tokens In + Out) / Completed Tasks.
## 6. Threat Isolation & Data Security
Treat everything touching the model as an attacker-controlled input.
- **Prompt Injection Vectors:**
	- *Direct:* User messages.
	- *Indirect:* Retrieved RAG documents or poisoned tool outputs.
- **Execution Isolation:** NEVER execute raw SQL or shell commands generated by model text.
- **Data vs. Instructions:** Separate system instructions from user data. A retrieved document or tool output should never be allowed to override your core system prompt.
- **PII Masking:** Mask sensitive fields *before* logging the trace, and only pass required fields to the LLM.
