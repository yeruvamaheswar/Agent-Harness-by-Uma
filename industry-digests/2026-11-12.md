## Items

### 1. Deny, do not wait, on permission prompts in unattended runs
- Source: [Claude Code changelog 2.1.319 (2026-11-06)](https://code.claude.com/docs/en/changelog)
- Idea: The new `permissions.denyInsteadOfPrompting` setting denies a tool call that would wait on a prompt. The turn continues. This works in the terminal, in subagents, and in teammates.
- Proposed change: In the `autonomous-engineering` preflight, start overnight Claude runs with this setting on. The engine records each denial as a blocker, and the run does not stall. This targets a past failure, when a plan-mode prompt waited all night.
- Target: `tools/agents/skills/autonomous-engineering/SKILL.md` (preflight step 1). Optionally a per-run settings file written by `scripts/ae.ts`. Not the global settings.
- Repo check: `denyInsteadOfPrompting` does not appear in either harness root.
- Effort: S.

### 2. Tell Claude it owns the code in slice handoffs
- Source: [Anthropic, "Prompting Claude Fable 5.2"](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-fable-5-2#say-who-owns-the-code), via [Simon Willison (2026-11-10)](https://simonwillison.net/2026/Nov/10/prompting-claude-fable-52/)
- Idea: The sentence "You are the owner and long-term maintainer of this codebase, and its design is up to you" raised duplicate-code consolidation from under 10% of runs to about 75%.
- Proposed change: Add an optional ownership line to the slice handoff note, used only when the slice is allowed to restructure code. It conflicts with "no unrelated cleanup", so it must name the files in scope.
- Target: the handoff note in `tools/agents/skills/multi-agent-planning/SKILL.md`. Do not add it to `knowledge/core.md`.
- Repo check: no ownership phrasing exists. The Fable 5.2 tier rows already exist in release 1.6.2, so they are not proposed again.
- Effort: S, plus a small A/B eval on one refactor slice.

### 3. Add a memory consolidation ("dreaming") pass
- Source: [Anthropic, "The components of agent memory" (2026-11-06)](https://www.anthropic.com/research/components-of-agent-memory)
- Idea: Offline passes check memory notes against transcripts and the environment. They fix wrong notes, merge duplicates, and keep the injected index small. Wrong notes that stay in memory cause repeated failures.
- Proposed change: Add a weekly scheduled task that reads each memory file and checks dated claims against git and the repos, for example "uncommitted", "awaits merge", or "points at the old folder". It proposes edits or deletions in a report and never writes them itself.
- Target: a new reference, `knowledge/references/memory-consolidation.md`, plus a scheduled task prompt. Optionally a skill under `tools/agents/skills/`.
- Repo check: there is no memory guidance or consolidation in `knowledge/`, `tools/`, or `src/`.
- Effort: M.

### 4. Pin the Claude Code version range in the DesignOS plugins
- Source: [Claude Code changelog 2.1.323 (2026-11-12)](https://code.claude.com/docs/en/changelog)
- Idea: The new `engines["claude-code"]` field in `plugin.json` stops install, update, and load outside the stated range. `claude plugin validate --strict` now fails on warnings.
- Proposed change: Add `engines` to the three DesignOS plugin manifests. Add a `claude plugin validate --strict` step to CI.
- Target: the DesignOS repo root `plugin.json`, `plugins/design-os-impeccable/plugin.json`, `plugins/design-os-media/plugin.json`, `.github/workflows/check.yml`.
- Repo check: no manifest has `engines`. The Impeccable hooks are JSON, so the new TypeScript hook type check does not apply.
- Effort: S.

### 5. Use the Codex agents command center for Codex children
